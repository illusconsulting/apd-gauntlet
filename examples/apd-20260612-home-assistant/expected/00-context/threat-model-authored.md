## Highest-signal grounded threats

These are the strongest code-grounded (high-confidence) threats authored against cited `code-evidence-index.yaml` pointers — the ones the evaluator should weight most heavily.

- **[E / Authenticity + Integrity] Docker socket / host-root control plane (/run/docker.sock)** — _high_ — Terminal host-root escalation: add-on → Supervisor role gate (`cev-b2000001/2`) → Docker socket (`cev-b2000003`) → `container_run_inside` (`cev-b2000004`) = arbitrary container exec = host root. The top HA crown jewel.
- **[E / Authenticity + Integrity] os-agent (Go D-Bus host daemon)** — _high_ — Container→host-root bridge: `AddSSHAuthKey` (`cev-c3000001`) writes a root `authorized_keys` entry with **no in-method caller authorization**; Supervisor invokes it over D-Bus (`cev-0a000004`).
- **[D / Availability] os-agent (Go D-Bus host daemon)** — _high_ — `ScheduleWipeDevice` (`cev-c3000002`) schedules a datadisk/factory wipe over D-Bus with no in-method authz — catastrophic, recoverable-only-from-backup destruction.
- **[E / Authenticity + Integrity] mobile_app integration backend (registrations + webhook in Core)** — _high_ — Bearer-less `webhook_call_service` (`cev-a1000015`) calls **arbitrary** services (locks/alarms) under a synthesized context with **no per-entity permission check** — a leaked `webhook_id` (`leaked_device_webhook_id`) is unscoped device control.
- **[I / Confidentiality] Supervisor backup archive store (full/partial snapshots)** — _high_ — `Backup.set_password` defaults to `None` (`cev-b2000006`): default backups are UNENCRYPTED and bundle password hashes, `jwt_key`s, integration secrets and the recorder PII DB — the 'weakest-protected copy of everything.'
- **[I / Confidentiality] Refresh-token / JWT signing key store (per-refresh-token jwt_key)** — _high_ — Per-token `jwt_key`s are in PLAINTEXT `.storage` (`cev-a1000017`, `cev-a1000003`): disclosure permits offline forgery of valid HS256 access tokens (`cev-a1000001`), including owner-scoped (`cev-a1000008`).
- **[I / Confidentiality] .storage/auth + auth_provider.homeassistant (user credentials store)** — _high_ — bcrypt hashes + MFA/TOTP seeds in plaintext `.storage` (`cev-a1000017`), 0600-only — file/backup read yields offline cracking AND TOTP-seed theft.
- **[I / Confidentiality] Recorder history DB (SQLite/MariaDB/PostgreSQL)** — _high_ — The home-occupancy/geolocation/lock/alarm privacy fact base (`session_scope`, `cev-a1000018`) is stored at rest with no encryption — the PHI-equivalent disclosure surface.
- **[I / Confidentiality] Android Companion app (Kotlin, WebView, Keystore, FCM)** — _high_ — Room `AppDatabase` is built with no SQLCipher (`cev-f6000003`): `location_history` (raw lat/long) AND `ServerSessionInfo` bearer tokens (`cev-f6000004`) are UNENCRYPTED SQLite at rest.
- **[I / Confidentiality] JS external-auth bridge (window.externalAppV2 / webkit.messageHandlers)** — _high_ — The token-passing native↔WebView channel (`cev-07000001`) crosses in cleartext within the WebView; the frontend is served REMOTELY, and callback-name verification (`cev-07000002`) is doc-recommended but not enforced in the indexed code.
- **[E / Authenticity + Integrity] Add-on containers (third-party Docker images w/ config.yaml role/AppArmor)** — _high_ — An add-on with admin role or protection mode off matches `ROLE_ADMIN=re.compile('.*')` (`cev-b2000002`) and reaches the full Supervisor API → Docker socket → host root.
- **[E / Authenticity + Integrity] Core REST API (/api/, port 8123)** — _high_ — Function-level authz is admin-granularity only: state WRITE is admin-or-deny with no per-entity write policy (`cev-a1000012`); admin short-circuits per-entity filtering to allow-all (`cev-a1000007`); `@require_admin` template render (`cev-a1000013`) is an SSTI/SSRF primitive.

### Owner user (onboarding user, all permissions)

_2 cells — 1 grounded, 1 blocked_

- **S (Spoofing → Authenticity)** · `tm-901336d8` · _high_ · `[grounded]`
  - **Threat:** The owner identity is the unconditional all-access principal: auth/permissions/__init__.py::_OwnerPermissions (cev-a1000008) returns access_all_entities=True and an allow-all check fn, so spoofing or account-takeover of the owner (or an owner-equivalent long-lived token) bypasses the entire permission model. Spoofing applies because the owner principal authenticates over the same bcrypt credential path (Data.hash_password, cev-a1000004) and JWT bearer path (cev-a1000001) as any user, with no owner-specific step-up.
  - **Design-intent control (contradictable):** Login is bcrypt rounds=12 with a constant-time dummy-checkpw miss path (cev-a1000005) that defends user-enumeration; access tokens are HS256 JWTs validated centrally (cev-a1000002). MFA/TOTP is available as an auth module but is not asserted mandatory for the owner.
- **R (Repudiation → Non-Repudiation)** · `tm-a8308c32` · _low_ · `[BLOCKED]`
  - **Threat:** Owner-initiated consequential actions (state writes, service calls, add-on install, backup, user management) are not bound to a tamper-evident security audit log: the run scope confirms no audit_log_store exists (only logbook/logger), and the logbook sample shows context_user_id: null, so an owner can repudiate privileged actions. Repudiation applies to this principal because its actions have the highest blast radius and the weakest attribution.
  - **Prerequisite evidence (gap):** security audit-event log binding owner identity to privileged actions (confirmed absent: only logbook/logger; no audit_log_store)

### Long-Lived Access Token holder

_2 cells — 1 grounded, 1 blocked_

- **S (Spoofing → Authenticity)** · `tm-534bc7ae` · _high_ · `[grounded]`
  - **Threat:** A Long-Lived Access Token is a user-minted, long-horizon bearer issued from /profile; it authenticates as its owning user with that user's full permission set. Spoofing applies: anyone who replays a leaked LLAT is indistinguishable from the user, and an owner-issued LLAT inherits owner all-access (cev-a1000008). ### Home Assistant Core (Python asyncio app)

_6 cells — 5 grounded, 1 blocked_

- **S (Spoofing → Authenticity)** · `tm-8b2483ae` · _high_ · `[grounded]`
  - **Threat:** Core is a single, highly-privileged trust domain (overview lines 20-22) whose inbound auth is centralized: auth_middleware (cev-a1000009) accepts bearer, signed-query, or the supervisor unix socket and sets KEY_AUTHENTICATED. Spoofing applies because owner takeover (cev-a1000008) or a forged HS256 JWT (signed with a compromised per-refresh-token jwt_key, cev-a1000001/3) authenticates as any principal across this single privileged domain.
  - **Design-intent control (contradictable):** Central REST auth middleware (cev-a1000009) and the WS handshake (cev-a1000010) validate tokens; access tokens are HS256 JWTs validated at one chokepoint (cev-a1000002).
- **T (Tampering → Integrity)** · `tm-d98660ae` · _medium_ · `[grounded]`
  - **Threat:** Integrations are NOT sandboxed from each other and run with Core's full privilege (overview lines 20-22), so any tampering primitive inside one integration (or a malicious integration) tampers with all Core state, the permission engine, and .storage. Tampering applies: there is no in-process integrity boundary protecting Core's state machine from a single misbehaving integration.
  - **Design-intent control (contradictable):** None: integrations run unsandboxed at Core's full privilege by design (overview lines 20-22) — there is no in-process integrity boundary protecting Core state from a single integration.
- **R (Repudiation → Non-Repudiation)** · `tm-034d8894` · _low_ · `[BLOCKED]`
  - **Threat:** Core actions are recorded only in logbook/logger, not a tamper-evident security audit log (no audit_log_store; logbook context_user_id observed null). Repudiation applies across the whole Core action surface.
  - **Prerequisite evidence (gap):** tamper-evident security audit log for Core actions (confirmed absent: only logbook/logger)
- **I (Information Disclosure → Confidentiality)** · `tm-3ebbf8c2` · _high_ · `[grounded]`
  - **Threat:** Core holds and serves the dense secret/PII estate: .storage is written as PLAINTEXT JSON (cev-a1000017) and /api/config returns instance latitude/longitude + config_dir in cleartext to any bearer holder. Information disclosure applies because Core's single privileged domain means any auth bypass or over-broad token reads the full estate.
  - **Design-intent control (contradictable):** Per-entity READ policy is enforced at the state view (cev-a1000011); .storage files are 0600 (self._private) though plaintext.
- **D (Denial of Service → Availability)** · `tm-296e2800` · _medium_ · `[grounded]`
  - **Threat:** Core is a single asyncio process on a single host by design (no clustering claim); denial of service applies as a single point of failure — exhausting the event loop, the recorder DB, or the host crashes the whole automation platform including locks/alarms.
  - **Design-intent control (contradictable):** None claimed beyond OS limits: Core is a single asyncio process on a single host (no clustering claim); there is no documented rate-limit or HA/cluster mode.
- **E (Elevation of Privilege → Authenticity + Integrity)** · `tm-6f42b4af` · _high_ · `[grounded]`
  - **Threat:** Elevation of privilege is the dominant Core risk: state WRITE is admin-or-deny with no per-entity policy (cev-a1000012), the admin path short-circuits per-entity filtering to allow-all (cev-a1000007), owner is unconditional all-access (cev-a1000008), and @require_admin server-side template render (cev-a1000013) is an SSTI/SSRF primitive reachable post-admin. Elevation applies: crossing to admin/owner yields total control of the single privileged domain.
  - **Design-intent control (contradictable):** Admin gating on writes/templates (cev-a1000012/13) and compile_policy deny-all default (cev-a1000006) bound non-admin escalation; the gap is the coarse admin granularity, not absence of a gate.
