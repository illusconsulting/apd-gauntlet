# Agentic AI common patterns — Distributed

These are illustrative templates, not all-inclusive. Use them to calibrate analytical style, severity assignment per the agentic-AI rubric, and NIST/ATT&CK mapping habits. The specialist agent's checklist still drives the actual analysis — this file only calibrates how distributed-topology findings and capabilities should read once written. This is a pure topology lens: confidentiality of replicated/held-out data and content-trust of replicated state are named and routed out, never owned here.

## Common finding patterns

**Pattern: The agent orchestrator / control plane is a single coordination authority with no replication across failure domains and non-externalized coordination state.**

- Severity: high (blast-radius: a single-instance, single-AZ loop driver or task router is the failure domain for every in-flight agent and every multi-agent workflow at once; low reversibility because in-flight coordination state is lost on failure)
- NIST: SC-7, CP-7, CP-10, CM-2
- Related concerns: resilient (blast-radius of the shared coordinator); availability (uptime target for the control plane); ephemeral (resumability of coordination state)
- Detail: The plan->act->observe loop driver, generation scheduler, or tool-dispatch broker is the star-topology coordinator most agent systems route through (OWASP LLM06 Excessive Agency concentrated in one control authority; LLM10 amplifies because a stalled coordinator still holds budget). MITRE ATLAS LLM Plugin Compromise frames the orchestration/tool-dispatch surface as prose context; MAESTRO L3 Agent Frameworks and L7 Agent Ecosystem locate the coordination authority, L4 Deployment & Infrastructure the placement. In hexo-ai/sia the Feedback Agent driving Meta-Agent -> Target Agent -> evaluate across --max_gen is a single sequential control plane whose coordination state (per-generation artifacts, agent_execution.json, current-best metric/lineage) lives only in runs/run_id/; a process/host failure mid-run cannot resume because next-generation selection state is not externalized. SIA is a single-node research harness, so treat this as a topology observation, not a production HA claim.

**Pattern: The model-provider / inference endpoint is a single point of failure — agents pinned to one provider, one region, one API key, or one model family.**

- Severity: high (blast-radius: every agent step depends on a model call, so one provider/region outage or single-key throttle stalls the entire agent population simultaneously; autonomy means agents cannot self-substitute the dependency)
- NIST: SC-7, CP-7, SR-3, SR-4
- Related concerns: resilient (provider failover behavior); availability (provider SLA / rate-limit headroom); ephemeral (the provider key lifecycle, routed out)
- Detail: Pinned inference is a supply-chain topology dependency (OWASP LLM03 Supply Chain; LLM10 Unbounded Consumption where one shared quota is the chokepoint). MITRE ATLAS ML Supply Chain Compromise grounds the model-provider dependency as prose context; MAESTRO L1 Foundation Models is the inference dependency itself and L4 Deployment & Infrastructure the routing/key surface. hexo-ai/sia calls multiple model-provider APIs via the Claude Agent SDK + OpenHands for the Meta-Agent, Target Agent, and Feedback Agent; if all three roles route to the same provider/region or share one key per provider, that provider is a SPOF for the whole self-improvement run. The multi-provider-key setup mitigates only if the roles are actually distributed across providers rather than all defaulting to one. Failover behavior and SLO targets are routed out of lens.

**Pattern: Agent working state is pinned in worker memory, putting the stateful/stateless boundary inside the worker so it cannot be load-balanced, rescheduled, or replaced.**

- Severity: medium to high (autonomy/blast-radius: in-process conversation, scratchpad, partial-plan, and tool-call context make the worker stateful, so eviction/restart/AZ loss takes the active task down with it and sticky routing recreates a per-agent SPOF)
- NIST: SC-7, CP-7, CM-2
- Related concerns: resilient (recovery on worker loss); ephemeral (in-process state lifetime vs externalized store)
- Detail: This is the agent analogue of in-process session state (OWASP LLM06 Excessive Agency owning more state than is externalized; LLM08 Vector & Embedding Weaknesses where the working set includes retrieval context). No clean ATLAS technique applies — it is a state-boundary topology concern, so ATT&CK stays empty on the emitted finding. MAESTRO L3 Agent Frameworks holds the working state, L4 Deployment & Infrastructure the scheduling substrate. In hexo-ai/sia the Target Agent state (the generated target_agent.py, its in-run execution context, agent_execution.json) is materialized to the local run directory, which aids single-generation resumability; but the orchestration's in-flight selection/lineage state across generations is in-process. The stateful boundary is the per-generation artifact directory — interchangeable workers would require the active-generation working state, not just the completed-generation log, to be externalized.

**Pattern: Multi-agent message-routing topology and the CAP position under network partition are unspecified — no stated consistency-vs-availability choice when the agent set splits.**

- Severity: medium to high (autonomy/blast-radius: partitioned sub-agents acting autonomously on a stale or diverged shared goal is a goal-divergence cascade rooted in topology; severity rises with how consequential the partitioned agents' actions are)
- NIST: SC-7, CP-7, AC-4, SI-7
- Related concerns: resilient (behavior once the partition is hit); integrity (goal-divergence as a write-correctness consequence); authenticity (Sybil/impersonation as the adversarial route to a split, routed out)
- Detail: The inter-agent fabric (broker, blackboard, shared task queue, or direct peer routing) must declare its routing topology (star/mesh/queue) and the CAP choice under partition — prefer consistency (pause minority-partition agents so they cannot act on stale shared state) or availability (let them keep acting on a possibly-stale objective). An unspecified partition policy means partitioned agents pursue a diverged goal (OWASP LLM06 Excessive Agency exercised on stale state; LLM09 Misinformation as the diverged-output consequence). MITRE ATLAS LLM Prompt Injection is the cross-agent goal-manipulation vector as prose context; MAESTRO multi-agent collusion, agent impersonation, and inter-agent communication interception (L7 Agent Ecosystem) are the prose anchors, with L3 Agent Frameworks and L2 Data Operations on the routing/state substrate. Whether the partition is reached adversarially is prose; only the topology/consistency choice is the in-lens artifact. In hexo-ai/sia this is n/a in its pure form — SIA is a sequential single-node pipeline (Meta -> Target -> Feedback) with no concurrent mesh to partition — so the analog is a stale lineage/best-metric handoff between generations; the pattern is carried for the broad multi-agent surface the pack must serve.

**Pattern: A shared vector store / long-term agent memory has unstated SPOF status, replication topology, data locality, and cross-region write-consistency model.**

- Severity: medium to high (blast-radius: a single-instance store is a SPOF for every agent that depends on retrieval; async cross-region replication lets an agent in region B retrieve stale or not-yet-replicated memory written in region A, producing behavior divergence from a consistency gap)
- NIST: SC-7, CP-7, AC-4, SI-7
- Related concerns: resilient (recovery of the shared backing service); integrity (content-trust of replicated state, routed out); confidentiality (leakage into a replica an agent can read, routed out)
- Detail: A shared retrieval store many agents read and write concurrently raises the locality/replication/consistency questions (OWASP LLM08 Vector & Embedding Weaknesses for the store as coordination substrate; LLM02 Sensitive Information Disclosure only as the routed-out replica-leakage consequence). No ATLAS technique cleanly covers the topology concern — ATLAS content-side techniques touch the integrity/confidentiality face that is routed out — so ATT&CK stays empty here. MAESTRO L2 Data Operations is the memory store, L4 Deployment & Infrastructure the replication placement. hexo-ai/sia's persistent state is the benchmark with held-out private ground truth (data/private/, evaluate.py) plus the runs/run_id/gen_n/ tree rather than a vector store; in lens this is a data-locality and replication-topology observation — the private ground truth is a single-locality store whose locality gates every generation's score, and replicating it for HA would make cross-region consistency of that ground truth its own inconsistency surface. Detecting poisoned embeddings routes to Integrity; confidentiality of the held-out set routes to Confidentiality.

**Pattern: Sub-agent fan-out and recursive delegation concentrate inference load on one endpoint/key/worker tier with no bounded fan-out or cross-endpoint load distribution.**

- Severity: medium to high (blast-radius: planner/worker and recursive sub-task delegation self-amplify into a self-inflicted hot spot, and a single throttled endpoint then stalls the whole fan-out for the agent population)
- NIST: SC-7, CP-7, RA-9
- Related concerns: resilient (runaway-loop kill switch and per-task spend ceiling, routed out); availability (concurrent-capacity headroom)
- Detail: Parallel tool calls, spawned worker agents, and recursive delegation distribute work, but without load distribution across inference endpoints and worker pools the fan-out concentrates and self-amplifies (OWASP LLM10 Unbounded Consumption as the resource-amplification framing; LLM06 Excessive Agency where an agent spawns sub-agents without a fan-out bound). MITRE ATLAS LLM Denial of Service frames the resource-amplification as prose context; MAESTRO L4 Deployment & Infrastructure (endpoint/worker tier), L3 Agent Frameworks (orchestration/fan-out), and L5 Evaluation & Observability locate it. In hexo-ai/sia fan-out is bounded structurally by --max_gen depth rather than concurrent breadth, but each generation's target_agent.py executes arbitrary Python, so an emergent generated target could spawn unbounded parallel work or recursive inference calls that concentrate on the shared provider/key. The distributed concern is that all generations route through the same inference endpoints/keys, so generated-code fan-out has no load-distribution headroom. The per-task spend ceiling and kill switch are Resilient/Availability and routed there.

**Pattern: Tech artifacts assert multi-region or multi-provider distribution but do not specify the active topology — single vs multi-provider/region routing, replica/quorum design, or which roles route where.**

- Disposition: uncertainty or blocked
- prerequisite_evidence: "Distribution topology specification — per-role inference routing (which agent role uses which provider/region/key), whether inference routing distributes across endpoints, replica/quorum design for any shared orchestrator or state/memory store, and the cross-region write-consistency model for replicated agent memory or held-out data"

## Common capability patterns

**Pattern: Replicated, stateless control plane with externalized coordination state — the orchestrator/loop-driver runs across failure domains and its run/lineage state lives in a redundant store so a replacement instance resumes in-flight workflows.** Nascent when the loop driver is single-process/single-host (typical of research harnesses like SIA); developing once coordination state is externalized to a redundant store; robust requires evidence of a successful control-plane failover with in-flight resume across an AZ or host loss.

**Pattern: Multi-provider / multi-region inference routing with per-role distribution and partitioned key/quota surface, so no single provider, region, or key is a SPOF for the agent population.** Nascent when multiple keys exist but all roles default to one provider/region; developing when roles are demonstrably distributed across providers; robust requires evidence that inference routing redistributes across endpoints under a provider outage or single-key throttle without stalling all agents.

**Pattern: Stateless interchangeable workers with all agent working state (scratchpad, plan, tool-call context, retrieval set) externalized to a redundant store.** Nascent from a design that names the externalization target; developing with service/IaC configuration showing the externalized store; robust requires evidence of an agent task surviving worker restart/eviction/reschedule without losing working context.

**Pattern: Explicit multi-agent partition policy — declared routing topology (star/mesh/queue) and a stated CAP position so partitioned agents either pause (consistency-preferring) or act on bounded-staleness state, with cross-region memory write-consistency specified.** Nascent when the topology and partition behavior are undocumented; developing when the consistency-vs-availability choice and write-consistency model are stated; robust requires evidence (partition test or chaos exercise) that minority-partition agents behave per the declared policy rather than acting on diverged shared goal/state.
