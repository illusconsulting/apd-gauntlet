# Agentic AI common patterns — Resilient

These are illustrative templates, not all-inclusive. Use them to calibrate analytical style, severity assignment per the agentic-AI rubric, and NIST/ATT&CK mapping habits. The specialist agent's checklist still drives the actual analysis — this file calibrates how findings and capabilities should look once written. Resilient owns the blast-radius-isolation facet of Excessive Agency (OWASP LLM06); name the other facets (read-scope, tool/write-authz, permission-lifetime) in Related concerns rather than designing them here.

## Common finding patterns

**Pattern: No circuit breaker on the autonomous self-improvement / task loop — the loop rolls to the next generation on hallucinated progress, reward-hacked metric gains, or an injected goal that never converges.**

- Severity: high (autonomous and cross-generation: an unbreakered loop amplifies a single bad generation across all subsequent ones and mutates artifacts without human confirmation; rises toward critical when the propagated behavior is a backdoor or unsafe self-modification)
- NIST: SI-4, SC-5, CP-13, RA-5, AU-6
- Related concerns: integrity (write-authz facet of agency on the self-modification merge); ephemeral (kill-switch to expire the rogue generation's compute); availability (loop-consumption ceiling — merged finding flags via related_concerns)
- Detail: OWASP LLM06 (Excessive Agency) on the loop-termination axis, amplified by LLM10 (Unbounded Consumption) and LLM09 (Misinformation/hallucinated convergence). ATLAS LLM Prompt Injection (AML.T0051) is the loop-steering vector and LLM Jailbreak the guardrail-bypass that keeps it running; sits at MAESTRO L3 (Agent Frameworks — the orchestration loop) and L5 (Evaluation & Observability — the metric that should arm the breaker). In hexo-ai/sia the Feedback Agent rewrites target_agent.py across --max_gen generations on a scalar metric; the breaker must trip on signals beyond max_gen — N consecutive generations with no held-out improvement (public-set gain while data/private/ ground truth via evaluate.py stagnates or regresses is the overfitting / reward-hacking tell), repeated identical-diff rewrites, or a spiking execution error-rate — then halt the run_id, freeze runs/run_id/gen_n/ artifacts, and page a human rather than silently rolling to gen_n+1.

**Pattern: Retry on model and tool calls without exponential backoff, jitter, or a bounded per-dependency budget — naive retry on 429/5xx/timeout.**

- Severity: high (autonomous synchronized retry storms self-inflict provider rate-limit lockout and runaway spend; a retried non-idempotent tool call produces irreversible duplicate side effects — double file write, double external POST, double sub-agent spawn)
- NIST: SI-13, SC-5, CP-10
- Related concerns: integrity (idempotency of the retried tool side-effect and of the agent_execution.json append — retry-without-idempotency is duplicate-mutation risk); availability (provider-quota exhaustion ceiling)
- Detail: OWASP LLM10 (Unbounded Consumption) with LLM05 (Improper Output Handling — re-issuing a side-effecting tool call on retry). Relates to ATLAS LLM Denial of Service / resource-exhaustion and cost-harvesting abuse against the model endpoint; MAESTRO L3 (retry middleware around tool/model clients), L1 (provider rate-limit behavior), L4 (provider quota exhaustion). In hexo-ai/sia the Meta/Target/Feedback agents call multiple provider keys and the target runs arbitrary Python that itself hits tools/network; fixed-interval retry across all three agents synchronizes into a storm that drains every key's quota at once — correlated failure of the supposed redundancy. Each generation should carry a per-dependency retry budget, and a retried target-execution step must be idempotent or guarded so a re-run does not double-append to agent_execution.json or double-spend downstream.

**Pattern: No bulkhead or resource isolation around code-exec sandboxes and per-agent quotas — generated code and sub-agents share a thread pool, container host, disk, file-descriptor table, API-key pool, and message bus.**

- Severity: high (one runaway or hostile unit — a fork-bombing generated script, a sub-agent stuck in a tool loop, a single tenant's task — starves every concurrent agent/run; blast radius crosses run and tenant boundaries, the irreversibility/blast-radius modifiers both apply)
- NIST: SC-6, SC-39, SI-13, CM-2, AC-6
- Related concerns: integrity (tool/write-authz facet of agency — the sandbox as enforcement point for a write-authorization contract is Integrity's; here it is a fault-isolation bulkhead only); confidentiality (read-scope — no cross-run artifact reach into sibling runs/ or data/private/); ephemeral (per-execution ephemeral sandbox lifetime)
- Detail: OWASP LLM10 (Unbounded Consumption), LLM06 (Excessive Agency — blast-radius facet), LLM05 (executing generated output). Relates to ATLAS compromised-agent code-execution and resource hijacking via generated code, with LLM Prompt Injection as the trigger that turns a sub-agent rogue; MAESTRO L4 (sandbox/container isolation, cgroups/ulimits), L3 (per-agent resource accounting), L7 (cross-agent resource contention in multi-agent deployments). In hexo-ai/sia the Target Agent executes Meta-Agent-generated Python; a bulkhead must cap each generation in its own resource-limited sandbox (CPU / mem / wall-clock / disk / network ulimits, no reach into sibling runs/run_id/ trees or data/private/) so a runaway or hostile script cannot starve concurrent run_ids, exhaust the host, or touch another generation's artifacts, and each run_id should draw from an isolated slice of the API-key pool.

**Pattern: No timeout discipline on autonomous steps, tool calls, and reasoning chains — no per-step wall-clock deadline and no total budget on the chain.**

- Severity: high (a single hung step — a tool call that never returns, a stalled model request, a generated subprocess blocked on stdin/network, a non-progressing reasoning chain — pins a worker indefinitely and the agent silently stops making progress with no failure signal; medium when only a single low-risk read-only step lacks a deadline)
- NIST: SI-13, SC-5, CP-10
- Related concerns: resilient (the deadline action overlaps the circuit-breaker pattern above — loop-termination logic decides what happens at the deadline); availability (liveness/progress detection for the stuck loop)
- Detail: OWASP LLM10 (Unbounded Consumption) and LLM06 (Excessive Agency). Relates to ATLAS LLM Denial of Service via long-running / non-terminating generation and tool invocation; MAESTRO L3 (per-step deadline enforcement), L1 (streaming/generation stall), L4 (subprocess wall-clock kill). In hexo-ai/sia the generated target_agent.py runs an arbitrary task; without a hard wall-clock timeout the execution step can hang on blocking I/O, an infinite loop in generated code, or a stalled provider call and pin the generation forever with no entry written to agent_execution.json. Each generation needs a per-execution timeout that kills the subprocess, a separate timeout on each Meta/Feedback model call, and a total per-generation deadline so a hung step deterministically fails the generation instead of hanging the whole run_id.

**Pattern: No graceful degradation when a model, tool, or guardrail is down — the agent fails open and keeps acting (proxies a raw error into a downstream action, or treats a check that errored out as a check that passed).**

- Severity: critical to high (a guardrail that fails open lets the agent keep taking consequential autonomous actions with no safety filter — critical when an unreachable/failed evaluator scores-as-pass and promotes a self-modification across generations; high when a model/tool outage produces confident hallucinated output instead of a deterministic fallback or halt)
- NIST: CP-12, SI-13, SC-5, RA-3
- Related concerns: integrity (the safety filter / output validator whose fail-open removes the injection defense is Integrity's content control); distributed (dependency replication/topology that provides the fallback); availability (dependency uptime SLO — graceful-degradation findings frequently merge with an Availability finding, flag via related_concerns)
- Detail: OWASP LLM06 (Excessive Agency), LLM09 (Misinformation), LLM05 (Improper Output Handling), and LLM01 (Prompt Injection — a down guardrail removes the injection defense). ATLAS LLM Jailbreak / guardrail bypass is functionally equivalent to a guardrail failing open, and LLM Prompt Injection succeeds once the validating filter is unavailable; MAESTRO L6 (guardrail availability), L1 (model fallback), L3 (degraded-mode orchestration), L5 (detecting the degraded state). In hexo-ai/sia a down primary provider must degrade deterministically (secondary key/model, or halt the run with a recorded reason) rather than emit low-quality rewrites that still get scored and promoted; critically, if evaluate.py errors, the held-out data/private/ ground truth is unreachable, or an output-safety check on generated code fails, the framework must NOT treat the missing/failed evaluation as a passing or default-high score — it must fail the generation safe and stop, not fail open and keep self-modifying.

**Pattern: No backpressure on generation / sub-agent fan-out or on the inter-agent message bus — unbounded queues, no admission control, no shed-load.**

- Severity: high (a planner spawns sub-agents unboundedly, a generation enqueues more candidate rewrites than the evaluator can score, or agents flood a shared bus; in-flight work accumulates into memory blowup or queue collapse, and a goal-manipulation/feedback cascade re-amplifies one agent's bad output across many before anything stops it — cross-agent persistence raises blast radius)
- NIST: SC-5, SI-13, AU-6, CP-10
- Related concerns: distributed (bounded fan-out and load-distribution topology across endpoints/worker pools); resilient (the breaker decides when to stop generations, backpressure decides how many may be in flight at once); integrity (the goal-manipulation cascade content is Integrity's, this owns the flow-control bound)
- Detail: OWASP LLM10 (Unbounded Consumption), LLM06 (Excessive Agency), LLM09 (Misinformation — cascade amplification). Relates to ATLAS multi-agent abuse / agent-impersonation flooding and LLM Denial of Service via unbounded fan-out; MAESTRO L7 (inter-agent communication, collusion/Sybil flooding, impersonation on the bus), L3 (bounded work queues, admission control), L2 (unbounded artifact/log accumulation). hexo-ai/sia is single-lineage per run_id, but fan-out backpressure still bites if multiple run_ids or multiple candidate rewrites per generation outrun evaluate.py: candidate scoring should be a bounded queue with shed-load, and runs/run_id/gen_n/ artifact + agent_execution.json growth should be bounded so an unbounded-generation run cannot fill disk; in a multi-agent variant, bound the per-planner sub-agent spawn count and rate-limit the inter-agent channel so one impersonating or runaway agent cannot flood peers and drive a goal-manipulation cascade.

**Pattern: Tech plan describes a "retry loop" or "max generations" without specifying backoff/jitter, per-dependency budget, idempotency interaction, the breaker's trip conditions, or the fail-safe-vs-fail-open degradation mode.**

- Disposition: uncertainty
- prerequisite_evidence: "Resilience policy specification — circuit-breaker trip conditions (metric-stagnation, public-vs-held-out divergence, identical-diff loop, error-rate spike) and trip action; per-dependency retry budget with backoff/jitter and the retried-step idempotency contract; per-step and per-chain timeout values with the kill action; and the documented fail-safe behavior when a model/tool/guardrail (including evaluate.py / the held-out scorer) is unavailable"

## Common capability patterns

**Pattern: Circuit breaker on the autonomous loop with documented trip conditions and trip action — halts the run_id and freezes artifacts rather than rolling to the next generation.** Nascent if only `max_gen` bounds the loop; developing when metric-stagnation and identical-diff trips exist; robust when public-vs-held-out divergence (the reward-hacking tell) arms the breaker and a halt-and-page action is evidenced.

**Pattern: Retry-with-jitter and an explicit per-dependency retry budget on model and tool calls, with an idempotency or guard contract on retried side-effecting steps.** Nascent from a tech-plan mention; developing once client-library backoff/jitter and per-dependency budgets are configured; robust requires chaos / game-day evidence that a provider-throttle does not synchronize into a key-pool-draining storm.

**Pattern: Bulkheaded, resource-limited per-generation sandboxes (CPU/mem/wall-clock/disk/network ulimits, no cross-run artifact reach) plus per-run API-key-pool slices.** Higher maturity when the deployment evidences the fault-domain boundary (cgroups/ulimits, network isolation) and the key-pool partitioning, not just a documented intent.

**Pattern: Deterministic graceful degradation — fail-safe-not-fail-open on model/tool outage and on guardrail/evaluator failure, so an unreachable scorer never promotes a self-modification.** Nascent when only a secondary model is named; robust when the guardrail/evaluator-unavailable path is shown to halt-safe rather than score-as-pass, with the degraded-mode transition observable.
